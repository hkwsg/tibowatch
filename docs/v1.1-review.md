# v1.1 review notes

Scope: published RSS forwarding, optional one-shot translation, unchanged production until review. The associated pull request records the exact HEAD/tree and hosted CI run.

## Behavior

The canonical source is https://savemetibo.com/feed.xml. Visible output is the parsed RSS title/description, or its selected translation, without local annotations. Status JSON selection, lifecycle mapping, keyword filtering and health Bark messages are removed. GUID plus title/body fingerprint replaces event interpretation. Date/link changes alone do not notify.

Forty offline tests pass on local Python 3.11. Compilation, install/activate/upgrade shell syntax and whitespace checks pass. Tests cover the 17 requested acceptance categories, including exact retry payloads, one translation attempt, no quiet-poll calls, malformed CLI output, process-group timeout cleanup, crash fallback, chronological batching, no-key retention, oversize retention and v1 migration safeguards. The old event-editorial tests were replaced by RSS behavior tests while retaining lock/backup/transport/retry/security coverage.

Read-only real-source validation using the application's named User-Agent parsed 22 RSS items. Initial generic HTTP attempts returned 403; no proxy/network changes or access-control bypass was used. No real Codex model request or Bark notification was sent during development.

## Codex strategy

One direct `codex exec` invocation, fixed `gpt-5.6-luna`, eight-second timeout, no alternate model and no translation retry. Input is JSON through stdin, not shell interpolation. The full invocation is documented in both READMEs. Noninteractive, ephemeral, ignore-user-config/rules, read-only sandbox, disabled shell/unified execution/web search, no project instructions, strict output schema and final-output JSON parsing are used. CLI stdout/stderr are discarded; Bark credentials are not inherited by the subprocess. Installed CLI 0.153.2 help confirms the invocation flags. Authenticated model availability is not assumed.

The English fallback and attempt marker are saved before invoking Codex. A crash after that point resumes with English instead of attempting translation again. At most five newly queued payloads are selected per poll; remaining work stays in the existing local queue. The eight-second cap plus five bounded HTTP sends keeps the normal batch within the existing oneshot time budget.

Selected payloads are immutable for Bark retries. Oversize selected content is retained with a local error rather than shortened. There is no semantic validation that a model preserved every meaning; JSON validation is structural only.

## State and deployment

State version 2 separates RSS fingerprints and pending exact payloads. Healthy-feed validation precedes migration. Any v1 pending entry blocks migration, including health entries, conservatively preventing silent loss. Migration keeps the existing installation-test marker and writes an additional protected v1 snapshot. The first RSS run baselines current items with no translation or replay; the second identical run is silent.

`deploy/upgrade.sh` pauses only this task's timer, refuses an active oneshot or unresolved queue, makes a protected pre-upgrade snapshot before installation, then verifies two new service runs before re-enabling scheduling. Errors leave the timer paused. It does not invoke installation testing or rewrite Bark configuration. The helper has not been executed on production; only its syntax and migration components were tested. Rollback requires matched old code/state, not running v1 against v2 state.

## Known gaps for review

- A local interactive user's authenticated CLI is not automatically available to the dedicated systemd account. Existing ProtectHome/resource restrictions remain; the operator must have a usable CLI/auth context for that user or accept immediate English fallback. No credential copying or privilege escalation is implemented.
- Live translation quality, account/model availability and translated phone delivery were not exercised. Tests use mocks and a strict subprocess contract.
- Feed availability is external; successful parsing does not establish continuous uptime.
- The 3000-byte outbound budget is deliberately conservative, not a claim about every Bark/APNs hard limit. Oversize jobs remain visible locally for intervention.
- Source failures pause forwarding until a healthy fetch and generate local status only. No external outage notification channel is added.
