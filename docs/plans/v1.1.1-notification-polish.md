# TiboWatch 通知展示小补丁执行计划

- 计划版本：1.0；日期：2026-09-13。
- 目标补丁：v1.1.1（本计划不自动授权发布 Release）。
- 已核验实现基线：`24428012f2cf3f22c26dd6598da4b771fb578841`，v1.1.0。
- 交接方式：以链接到本计划固定 commit 的新 GitHub Issue 为唯一任务入口；结果回贴同一 Issue。
- 当前交付是执行计划，不是已实现或已部署报告。

## 1. 本轮目标

只改善手机通知的展示与点击体验，保持 RSS 转发器的小体量：

1. 点击新通知不再自动打开 SaveMeTibo，消息留在 Bark 历史中方便阅读。
2. 概率直接放在标题末尾，例如 `Codex — 重置观察：86%`。正文不增加概率解释、Source、时间或链接尾注。
3. 保留上游文字里的 emoji；同一发布记录有可用图片时，可直接复用为 Bark 图标，不做图片生成或网页复刻引擎。

示例仅表达排版，不要求翻译模型每次给出相同措辞：

```text
Codex — 重置观察：86%

一次重大额度故障，使 Codex 再次重置成为可能。
```

已有规则继续有效：RSS 决定何时有新消息；只翻译一次；失败发英文；发送重试使用已经选定的内容；不做二次内容判断。此 Issue 对标题概率与图标的明确授权，覆盖 AGENTS.md 中原有的“不附加任何 annotation”口径，仅限复用上游信息，不授权新增本地解读。

## 2. 已核验的数据合同

执行者先读 Issue、AGENTS.md、docs/ENGINEERING.md 和当前源码，再从目标运行环境读回一次公开源。

### 概率必须匹配同一条发布快照

RSS：`https://savemetibo.com/feed.xml`。

补充信息：`https://savemetibo.com/status.json`，实际匹配路径是：

```text
RSS item.guid
    == status.events[].lifecycle[].approval_id
```

读取命中的 **lifecycle 条目**的 `chance_48h`、`state`、`share_card_url`。不是读取父 event 的当前字段，也不是首页当前概率或 change_log.value。

两个核验样例：

| RSS GUID / approval_id | 对应 lifecycle 状态 | 对应概率 |
| --- | --- | --- |
| `apr_031a4b0dc2f784f6e58091a44946e797` | watch | 86 |
| `apr_5f32e1706f0fcdfd291ce2a317241ff0` | watch | 97 |

第二个样例的父 event 后来已经变成 confirmed、概率为空，但这条旧发布快照仍为 watch / 97。这是必须保留的回归用例。[S1]

`landed` 快照的 `chance_48h` 可以为 null；SaveMeTibo 页面明确把已经完成的预测显示为 100%。本轮只对**匹配到的 lifecycle.state=landed**使用这项已核验的展示映射，不把任意 null/0 或父 event 的新状态统一转成 100%。`confirmed` 等其他状态缺少数值时，默认不加百分比；不要仅凭标题语气猜数值。[S1,S2]

Bark 官方 API 已明确：`url` 是点击跳转地址，`action=none` 会禁用点击操作，`isArchive` 支持字符串 `"1"`，`icon` 是自定义通知图标 URL，不是完整大图附件。[S3]

## 3. 最小实现

### A. 取消外跳并保留历史

在最终 Bark 请求构造处显式选择允许的字段，不再直接把整个内部 payload 展开到 HTTP JSON。

- 所有新发送和待重试发送都**省略 `url` 字段**，包括旧 pending 里遗留的 URL。
- 不用空 URL、主页 URL 或 `action=none` 替代。
- 设置 `isArchive: "1"`；保持现有 group、level 和密钥来源。
- 不在标题/正文末尾追加 RSS.link、Source 或其他链接说明。
- 内部 RSS link/旧 state 的 url 可以保留，以避免无意义迁移；它们不得再穿透为 Bark 点击参数。
- 这只影响补丁后的发送；不重发、删除或改写手机里已经收到的历史通知。

### B. 概率和图片只是一次性的补充信息

继续先按原始 RSS GUID + title/body 指纹识别新增/正文变化。

只有本轮有需要选择内容的 `awaiting` 项时，才额外读取一次 status.json，供这轮最多五个任务共享。在内存中建立 approval_id 查找表即可；不增加常驻缓存、数据库、后台任务或每条一遍的 HTTP 请求。

补充读取使用正常 TLS、大小限制和一个短超时（建议 5 秒），失败不重试、不影响 RSS 健康状态、不阻止原通知进入翻译/发送。没有新候选、首次基线、只重试已经选定的 pending 时，不读取补充源，也不增加模型调用。

匹配要求：

- 仅匹配确切 approval_id；不使用事件数组顺序、相近标题或全站最新记录猜测。
- 同一 ID 出现冲突条目、核心结构异常或明显对不上这版正文时，省略该项补充信息，并保留正常转发。
- 正文一致性比较可做首尾空白规范化，不修改实际转发正文；时间只用于校验/诊断，不靠最近时间强配事件。
- 合法数值为 0–100 的有限数，排除 bool、NaN、无穷和不支持的类型；不把 0.86 自行乘成 86，不把空值当 0。整数不显示多余 `.0`，不随意取整改变上游数字。
- matched lifecycle.state=landed 时按第 2 节显示 `100%`；其他状态有合法数值则显示原数值，否则省略后缀。

### C. 标题拼接与翻译顺序

对上游原始 title/body 继续只调用一次现有翻译函数；概率由程序在翻译结果后拼接，不让模型生成或改动数字。

```text
显示标题 = 选定的中文/英文标题 + （有概率时的「：86%」）
显示正文 = 选定的中文/英文正文
```

中文翻译失败或被禁用时，英文标题同样可带 `：86%`。已带有同一百分比的标题不重复追加。没有概率时保留标题，不加“未知”“待确认”占位。

选择前保存带已确定补充信息的英文 fallback；翻译完成后保存最终标题/正文/可选图标。异常中断仍遵守现有“最多一次翻译”语义。Bark 重试不重译、不再次取概率、不重新拼冒号后缀。

**仅概率、图片、首页读数变化不触发新通知。** 指纹仍基于原始 RSS title/body，不把本轮新增展示字段加入去重依据；升级不会让全部旧消息重新出现。

### D. emoji 与可选视觉素材

上游 title/body 自带的 emoji 按文本保留，不自己添加一套状态表情。必要时只在现有翻译提示词中补一句保留 emoji，不加第二次模型调用或新的 Unicode 处理框架。

可选图标只使用命中 lifecycle 的 `share_card_url`，而不是父 event 会随状态变化的 share-card 地址。URL 须为正常 HTTPS、准确的 `savemetibo.com` 主机、无用户信息，且路径对应同一 event 和 approval 的公开图片；没有明确入口就省略。不抓网页、不 OCR、不画图、不上传图床。

开发时最多核验少量公开样例是否返回实际图片。运行时不由 watcher 下载/转换图片，只把有效的上游图片 URL 放入可选 `icon`。不要为图片增加同步请求链。

图片属于 best-effort：当前只确认上游提供了 URL 字段与 Bark 的 icon 能力，**未确认这些卡片在用户手机上的实际裁切效果**。如果样例不可用或只能得到不可读的缩略图，保留文字/emoji 路径，报告这一项即可，不阻塞取消外跳与概率补丁。不声称 icon 等同完整表情包/卡片像素复刻。

保留现有 3000 字节负载预算：组装时可在落盘前舍弃可选 icon 来保住文本；选定后重试不改变内容。正文不得为装饰而截断；文本本身超限仍走原有 pending 错误处理。

## 4. 兼容与改动边界

建议只增加少量函数：解析发布快照、计算标题后缀、构造 Bark 输出。主要改 `watcher.py`、相关测试及必要文档。

- 保持 state version 2；优先使用可选字段，兼容旧记录。现有校验要求的内部 url 字符串可继续保留，不为去掉外跳进行大迁移。
- 旧 selected pending：保留已选标题/正文，不追补概率或重译；仅在输出层去掉 url 并开启归档。尚未选择的 pending 可走新选择路径。
- 保留原始 observed/accepted 指纹、pending、锁/备份、安装测试标记。
- 固定现有模型、认证复用、30 秒翻译、240 秒 service、五分钟 timer、BATCH=5；不调资源限制，不加新账号或同步凭据服务。
- 补充信息失败是展示降级，不是源故障；原来的转发流程照常工作。
- README 双语示例改为标题概率、点击留在 Bark、可选上游图标；简短更新 ENGINEERING.md、AGENTS.md、DEPLOY_WITH_CODEX.md 中受影响的旧描述与 CHANGELOG 的未发布条目。不要重新组织整套文档。

## 5. 最低验收

保留现有相关回归覆盖，并增加以下行为测试；可合并测试方法，不为凑数量扩写：

| 场景 | 预期 |
| --- | --- |
| 新提醒及旧 pending 的真实出站 JSON | 没有 url/action；isArchive 为字符串 1；正文无新增尾注 |
| 命中 86 / 97 发布快照 | 后缀为 `：86%` / `：97%`，父 event 后续状态不串入 |
| landed / null | 按明确状态显示 100%；未知状态或未命中不能自动变 100% |
| 0、null、越界、bool、坏结构、重复冲突、正文不匹配 | 合法 0 保留；不可靠补充被省略，通知仍可发 |
| 翻译成功、失败、禁用与进程中断 | 正确选择中文/英文；后缀不重加，最多一次模型调用 |
| Bark 失败后重启重试，上游概率改变 | 重发同一选定版本，不重新翻译或抓补充数据 |
| 历史基线、静默轮询、只改概率/图标 | 零额外业务通知，零额外模型调用；静默不取 status.json |
| 同轮多个新条目 | 补充源最多请求一次，失败不拖住全部条目 |
| 原文含 emoji / 组合 emoji | 解析、持久化和发送路径不丢字符；不凭空加图标字符 |
| 上游图标合法、缺失、坏 URL、装饰导致超限 | 合法可选复用；其他省略图标，不泄漏为点击 URL |
| 已有 state v2 载入补丁 | 基线、去重、pending 和测试标记保持，不重新补发历史 |

执行现有离线检查及 CI：

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile watcher.py
sh -n deploy/install.sh
sh -n deploy/activate.sh
sh -n deploy/upgrade.sh
git diff --check
```

增加脱敏通知预览，至少展示 86%、97%、已落地、无可用概率、英文 fallback 五种情况。预览不发手机、不读真实密钥；从最终输出构造函数验证，而不是仅检查中间变量。

## 6. 执行与交付

### 本轮可连续执行

从最新 main 建独立 worktree/分支，例如 `fix/notification-polish-v1.1.1`。读取实际源合同 → 实现小补丁 → fixtures/离线测试 → 简短文档 → Draft PR → 回贴报告。无需重新提交架构方案。若 main 已有其他新改动，先核对差异，不覆盖他人工作。

开发期间生产不动，不发送真实 Bark 或模型测试。Issue #1、#3 已完成，不重新打开它们。这个补丁使用新的 Issue/PR。

回贴内容：

```text
READY_FOR_PM_REVIEW
HEAD / tree:

Tests / CI:

Legacy state/pending: PASS or actual result

```

### 代码批准后的现场验收

不需要重装、再次登录或重跑 state-v1 迁移。按现有 state-v2 小版本维护流程备份并更新，只操作本任务的代码与 timer，保留 Bark/runtime/auth/state。

批准进入现场阶段后，用一条明确标为“展示测试”、非真实重置公告的合成通知检查：标题后缀、正文、可选图标、Bark 历史保存、点击不外跳。不得重置旧 installation-test 标记或注入生产 RSS。服务接受与手机实收/点击结果分别记录；旧通知不用于验证新行为。

正常轮询与状态检查通过后回贴 `READY_FOR_PM_FINAL_ACCEPTANCE`。合并、关闭 Issue 和 v1.1.1 发布在最终验收后处理，不在开发中自动进行。无关 SSH、网络及其他业务不改。
